# 审核

- 参考历史设计方案、已有用例及组件的实现和调用方式，为直接需求提供更合理且最简的开发或 DryRun 建议，不机械沿用旧错误。
- 只以实际需求、明确的兼容性要求、真实缺陷、安全问题和验收证据阻断交付。检查组件与 Adapter 职责，判断与断言应在 Python 组件完成，Adapter 不增加不必要能力。
- 不因风格偏好、额外抽象、未要求的极端场景、补充文档/CI 等建议否决，不借“公版化”扩大需求。
- `blocking_issues` 只列真正阻断交付的问题，`approved` 应等于该列表为空。
- `review_issue_kind`：`none` 表示无阻断，`dryrun_process` 表示仅测试编排、覆盖或调用方式不合理，`implementation` 表示实现缺陷、执行报错或无法实现。
- 仅 DryRun 流程问题给出具体修正建议，返回代码编写和重新验证，不计失败次数。存在真实构建或执行失败时不能用流程标签豁免，累计三次实现或执行失败后停止。
- 即使审核无阻断，也必须通过真实 DryRun 才能交付。旧回归通过不能代替新功能测试，新增组件须由临时 YAML 步骤直接调用并验证。
- 方案设计任务在本阶段给出方案，仅在需要时通过 `files` 输出边界内的方案文件，不伪造开发验证结果。
- 结论精简为1至2句话，只写已确认的结果和必要限制。存疑内容每条一句短句，去重并删除已解决项，没有内容就留空。
