# 代码编写

按本次实际改动选择以下规范，混合任务同时遵循涉及的各节，不要求每次都修改三层。

## 通用要求

- 参考既有组件、用例的实现及调用方式，采用满足需求的最简设计，不机械复制已有错误；
- 正式源码不可直接写入，只通过 `files` 提议完整 UTF-8 内容，且仅限边界阶段声明的 `editable_files`；路径相对于 KDT 根目录，不加 `kdt/` 前缀；
- `scratch_files` 可提供相对当前会话目录的临时 YAML、C++、CMake、Python 夹具，也可在已授权的当前会话目录直接准备、构建和执行验证程序；构建产物、缓存与输出不能写到其他目录；
- 需要启动节点、生成代码或编译验证程序时自行准备夹具并清理进程，不让用户提供本可自行生成的验证输出；
- 功能验证与证据要求统一遵循同次加载的 `dry-run.md`，不能用旧回归代替本次新功能验证；
- 全局配置类的功能可以添加进 KDT 框架的 `kdt_config` 中，均为运行时确定，不提前配置。
- 通过 `from framework import kdt_config` 读取 `system`（如 `win`、`linux`、`macos`）和 `cpp_standard`（如 `17`、`20`、`23`，未知为 `None`），不自行猜测标准，环境信息也不能代替具体 Adapter 的能力检查。
- `kdt.config.ext` 仅在运行时提供 Python 无法直接获取的额外信息，以 JSON 对象输出，由 Python 框架解析、校验后加入 `kdt_config`，Python 能自行获取的信息不下沉到该 Adapter。

## 适配层（Adapter）

- C++ 最低标准采用 RMVL 约定的 C++17，如果有特性需要更高版本，必须添加条件编译宏；
- 对应 `adapter/` 中的 C++ 程序及必要构建配置，仅实现 Python 不便直接调用的 RMVL 底层操作和查询能力，如果有功能能通过Python组件实现，则不要在此添加，除非用户明确说明；
- 返回组件需要的数据，明确输出与退出码语义，不承担用例的预期判断，存在、相等、满足预期等判断与断言由 Python 组件完成；
- 优先复用已有命令和查询结果，不为组件能完成的判断增加专用命令，例如节点是否存在应由组件精确匹配 `lpss.tool node list`，不增加 `exists` 命令；
- 保持已有调用方式和平台、C++ 版本兼容约定，区分成功、运行错误和不支持，不把错误伪装成空查询结果，C++ 输出优先使用 fmt，不使用 iostream；
- 适配层修改必须实际构建，并通过临时 KDT YAML 验证修改后的程序，优先经已有组件调用，不能只测试临时替身或检查源码字符串。

## 组件（Python 关键字）

- 对应 `components/` 中的 Python 实现和 `components/keywords.yml` 注册定义，核对关键字 ID、绑定路径、参数类型、显示名称和说明与实际函数一致；
- 负责输入校验、必要的数据解析、返回值和业务判断，将通用功能封装为可复用关键字，不硬编码特定用例的节点名、路径或期望值；
- 查询失败、超时、不支持必须正常传播，不能误判为“未找到”，等待由独立等待组件负责，不混入其他判断组件；
- 能直接返回的数据就返回，便于后续断言引用步骤结果，避免仅为传递简单结果而转储文件；
- 优先复用适配层必要能力，不将组件判断下沉为新的 Adapter 命令，新增或修改的说明应明确返回值、失败语义及必要的兼容性限制，如果用了特定 C++ 版本才拥有的 Adapter 特性，必须在说明中明确指出，并且在用例调用时根据 `kdt_config` 中的 C++ 版本来决定是否使用；
- 新增组件必须准备直接调用新增关键字的临时 KDT YAML 功能用例，并验证真实返回值或可观察行为，不能只用系统命令或脚本绕过组件调用。

## 用例（YAML 与测试计划）

- 对应 `cases/` 的正式用例及 `plans/` 中的计划，优先组合已有关键字，不因单个用例方便而增加不必要的组件或适配命令；
- 描述清楚测试前提、输入、预期；按需填写 `background`、`input`、`expected`，类型限于空值、字符串或字符串列表，无前提可省略，不重复“已准备 RMVL”等通用环境说明；
- 以步骤返回值与 `{{ stepN }}` 完成简单断言，确实测试文件行为时再使用文件校验；少用 `fs_command` 等系统命令组件，不能绕过本次需验证的组件；
- 明确步骤的 `dep` 和清理顺序，失败后仍需执行的清理步骤不依赖上一步，避免泄漏进程或临时资源；调整步骤时同步维护后续引用编号；
- 正式用例必须加入本次新增或修改的测试计划，AI 编写的用例和计划在顶层 `info` 后增加 `ai_created: true`；
- 用例开发以正式 YAML 验证本次目标，组件或适配层开发使用的临时功能用例留在会话目录，不混入正式用例集合；混合任务分别提供两类验证。
