# DryRun

本阶段由桥接层实际执行验证，以下规则也供代码编写和审核阶段使用。

- 功能测试必须通过真实 KDT YAML 执行，不以直接执行 Python 脚本代替。脚本可作为组件调用的必要测试夹具。
- `functional_checks` 与 `acceptance_checks` 逐项同名对应，每项包含 `name`、`case`、`yaml`，`case` 与 `yaml` 二选一，未用字段填空字符串。
- 组件或适配层开发：`yaml` 指向当前会话目录的临时 `.yml` / `.yaml`，`case` 为空。临时用例不得放进正式 `cases`。所有新增注册关键字必须由临时用例的步骤直接调用，不能只在命令字符串或说明中提及。
- 优先复用组件及步骤返回值，少用系统命令组件，仅用于必要的构建、夹具准备等辅助工作。既要调用新增组件，也要验证真实结果。
- 用例开发：`case` 为本次新增或修改步骤的正式点分用例 ID，`yaml` 为空。所有交付用例必须加入本次新增或修改的计划。混合任务同时满足临时组件验证与正式用例要求。
- 临时用例在当前会话目录运行，`KDT_ROOT`、`KDT_AI_SESSION_DIR` 可定位正式代码、Adapter 和夹具，临时输出留在会话目录。
- YAML 执行快照由桥接层按轮次归档到 `build/ai_assisstant-<key>/cases/round-N/`，失败或取消也保留。交付区记录用例名称、结果和完整定义，不能伪造通过。
- 必须验证实际交付代码或可执行文件，不能只检查源码字符串、临时替身或旧版本。Adapter 构建失败不执行后续功能用例。
- 未修改的旧用例和仅改名称、说明的用例只算回归，`functional_cases` 仅为补充用例，不能把旧用例变为新功能验证。
- 例如 `lpss.tool` 必须验证 node list/info、topic list/info、service list/info 六项需求，并按要求验证 C++17~C++23，不能用 basic_pubsub 代替。
- 分开记录功能与回归结果，缺少验收、失败或跳过不能标为成功。仅验证编排、覆盖或调用流程不合理可修改后补测，不占实现失败次数，真实构建或执行报错仍计数。
