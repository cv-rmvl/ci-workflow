# 明确边界

- 只读检查已有设计、实现及调用方式，列出本次允许修改的 `editable_files` 和不能修改的范围，不构建或执行测试。
- 路径相对于 KDT 根目录，不加 `kdt/` 前缀，仅限 `components`、`cases`、`plans`、`adapter` 中允许的源码文件。
- 以用户最直接的需求确定最小改动范围，不添加不必要的抽象、功能或外围工程。
- 不确定行为先参考历史设计方案，再依据工程和底层机制的合理语义判断。已有 Adapter 或组件确有错误时可以纳入本次修正，但必须在本阶段声明文件，不能擅自越界。
- 明确 Python 组件与 Adapter 的职责，Adapter 仅提供必要的底层能力和查询数据，存在性判断、比较、预期断言由组件完成。
- 提前确定新增组件如何被临时 KDT YAML 用例直接调用，正式用例如何加入测试计划，区分本次功能验证与既有回归。
- 无法在授权边界内完成的内容应说明限制，不能绕过权限或覆盖用户并发修改。
