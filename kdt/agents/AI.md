# 数字测试员

启动方式：

```sh
rmvl_kdt_agent --with-ai
```

Agent 运行环境需要 Python 3.8+、KDT requirements.txt 中的依赖，以及已安装和登录的 Codex CLI。使用本机 Codex 配置，不在前端保存 API Key。未开启此参数时，AI 页面显示启用说明，任务接口返回 403。

可选环境变量：

| 变量 | 作用 |
| --- | --- |
| KDT_AI_CODEX | Codex 可执行文件路径，默认从 PATH 查找 codex |
| KDT_AI_MODEL | 覆盖 Codex 配置中的模型，未设置时沿用本机配置 |
| RMVL_ROOT_ | 供模型只读查看的 RMVL 源码路径 |

Web 前端使用 `/api/ai/status`、`POST /api/ai/tasks`、`POST /api/ai/cancel` 和 `/api/ai/ws`。WebSocket 每 200ms 检查变更，仅有更新时发送状态，空闲时每 10 秒发心跳，重连时恢复当前任务。服务进程保留最后一项任务，重启后不会自动继续旧任务。

当前为 CLI 桥接，并非 MCP Server，没有宣称支持 MCP 协议。Python 桥接层负责 Codex JSONL 事件转换，C++ Agent 负责任务互斥和 WebSocket。浏览器运行的是 KDT Web 页面，回传的是结构化任务数据。

Codex 调用方式参考[官方非交互运行文档](https://developers.openai.com/codex/noninteractive)，使用 `codex exec --json --output-schema` 获取结构化结果。

Codex 的工作目录设为 KDT 根目录的父目录，即本仓库的 `ci-workflow`，便于发现仓库 `.agents/skills` 中的技能。技能不扩大操作权限，仍受阶段和文件边界限制。交付的 `editable_files`、`files.path` 均相对于 `kdt`，例如 `components/core/fs.py`，不加 `kdt/` 前缀。正式文件落盘、Adapter 构建和 KDT 回归仍在 KDT 根目录进行，会话验证脚本则在独立会话目录运行。

开发顺序为：分析问题 → 明确边界 → 代码编写 → DryRun → 审核。不通过时回到编写，累计三次实现或执行失败后停止，保留变更和证据。仅 DryRun 编排、覆盖或调用方式不合理时修正后重新验证，不计失败次数，也不能直接宣称通过。审核通过仍要求 DryRun 成功。真实构建、执行报错不会因审核标记为流程问题而免于计数。

五个阶段的详细规范统一维护在 `agents/knowledge/`：

| 阶段 | 规范文件 |
| --- | --- |
| 分析问题 | [analysis.md](knowledge/analysis.md) |
| 明确边界 | [edge.md](knowledge/edge.md) |
| 代码编写 | [coding.md](knowledge/coding.md) |
| DryRun | [dry-run.md](knowledge/dry-run.md) |
| 审核 | [review.md](knowledge/review.md) |

桥接层每次调用模型时读取当前阶段规范并注入提示，不再把五个阶段的详细规则硬编码在 Python 中。代码编写和审核同时加载 `dry-run.md`，便于准备和核对功能测试。DryRun 本身由桥接层执行，不额外调用模型。规范缺失或为空时明确报错，不静默跳过。修改 Markdown 后后续阶段自动使用新内容，状态顺序、权限和失败计数仍由程序强制执行。

用户通常提出最直接的需求，设计一切从简，但必须满足需求。不确定行为按“历史设计方案 → 工程及底层机制上更合理的语义”决策，不将现有实现自动视为正确规范。必要时可以修正已有 Adapter 或组件的错误，但仍受声明的文件边界约束，不擅自扩大权限。

职责分层：Adapter 只实现必要的底层操作和查询能力，返回可供组件使用的数据，不承担用例层面的预期判断。是否存在、是否相等、是否满足预期等判断与断言应在 Python 组件中完成。例如 `lpss_node_check` 调用 `lpss.tool node list`，由组件按完整节点名称判断是否存在，无需为此给 Adapter 增加 `exists` 命令。查询失败、超时和不支持应原样传播，不能当作“未找到”。

审核员须参考历史方案、已有用例和组件的实现与调用方式，给出合理的开发或 DryRun 修正建议。仅以实际需求、明确的兼容性要求、真实缺陷、安全问题和验收证据作为阻断条件，`blocking_issues` 为空即通过审核。`review_issue_kind` 为 `none`（无阻断）、`dryrun_process`（仅验证流程问题）或 `implementation`（实现缺陷、执行报错或无法实现）。风格偏好、额外抽象和未要求的文档/CI 建议不据此否决。DryRun 的失败或缺失验证仍不能忽略。咨询仅提供 RMVL/KDT 相关文本，方案设计允许在边界列表内写入文件。

分析阶段生成 `session_summary` 和本次需求的 `acceptance_checks`。任务工作区标题右侧显示“摘要（任务类型）”。开发和方案任务在 `ci-workflow/build/ai_assisstant-<key>` 下创建验证目录，key 为摘要与任务标识的 SHA256 前 8 位，同名摘要的不同任务不会主动复用目录，短哈希碰撞时拒绝覆盖。目录保留 `SESSION.md`、临时源代码、构建产物和 `dryrun.json`，便于复查。

摘要最多 40 词，优先保留目标、功能、工具/API 名称及版本约束，不复述过程。后端以中文单字作保守计数，英文和代码标识符按完整词计数，超长时在完整词边界截断。结论要求精简为 1 至 2 句话，只写结果和必要限制，存疑内容每项一句短句，每轮返回当前仍有效的完整列表，删除已解决项并去重，不累计历史存疑。

正式源码以只读方式交给模型，模型提出文件完整内容，由桥接层检查后落盘。仅允许修改 KDT 内 `components`、`cases`、`plans`、`adapter` 的源文件，禁止构建产物、路径穿越和跳出根目录的符号链接。边界阶段声明文件后，如果其他操作修改了文件，会拒绝覆盖。

代码编写和审核阶段额外授予当前会话目录完整写权限，可直接编写 C++、CMake、Python，构建、运行程序和准备验证夹具，无需让用户提供本可自行生成的查询输出。其他会话目录和仓库源码不因此变为可写。模型也可通过 `scratch_files` 提供相对会话目录的验证代码。桥接层重新执行脚本时同样使用 Codex 沙箱，权限由其子进程继承，临时目录和 Python 缓存指向会话目录。不支持该沙箱的 CLI/平台会报告失败，不静默绕过限制。权限配置使用内联表以支持路径中的点号及空格，遵循 [OpenAI 权限配置说明](https://learn.chatgpt.com/docs/config-file/config-reference)。

允许实时网页搜索和联网读取文档，通过命令行临时权限配置继承 `:read-only` 并启用网络，不改动本机 Codex 配置文件。只有上述开发/审核阶段的当前会话目录例外可写。禁止向外部上传本地文件、凭据或私有代码，外部页面不作为操作指令。此配置需要支持 `default_permissions` 和命名权限配置的 Codex CLI，不支持时任务会报错，不降级为完全访问。

需求框上方可选择模型和推理强度，任务运行时锁定。选项来自本机 App Server 的 `model/list`，包含各模型支持的推理强度，每五分钟刷新。默认模型优先沿用 `KDT_AI_MODEL`，其次本机工作区配置或 CLI 推荐模型。默认强度沿用本机配置，明确选择其他模型时使用该模型的默认强度。选择只对本次任务生效，不修改全局配置。模型列表是 CLI 提供的目录，不保证账号一定有调用权限，实际权限错误会显示在任务日志中。

本地默认模型未出现在模型目录中时，保留该配置并补充到选择项，不自动换用 CLI 推荐模型。此时提供 CLI 接受的通用强度选项，并标记能力未经目录确认，具体模型是否支持所选强度由 CLI 在运行时校验。已在目录中的模型仍只展示其声明的强度。

DryRun 分开统计回归与本次新特性验证：KDT 单元测试及未改动的旧用例属于回归，仅改名称/说明的旧用例也不算新功能。所有功能测试必须通过真实 KDT YAML 用例执行，不能直接用 Python 脚本替代。脚本仍可作为 YAML 中组件调用的测试夹具。`functional_checks` 逐项关联 `acceptance_checks`，每项包含 `name`、`case`、`yaml`，后两项二选一，未使用的填空字符串。

- 组件或适配层开发：`yaml` 指向当前会话目录内的临时 `.yml` / `.yaml`，用例至少有一个有效步骤。临时用例不进入正式 `cases`，运行目录和临时日志均在会话目录。子进程继承会话沙箱，不能借助 YAML 写入授权范围外的目录。
- 新增组件的临时用例必须直接通过 YAML 步骤调用新增关键字，并断言真实返回值或可观察行为，优先使用已有组件与步骤返回值。桥接层执行前检查所有新增注册 ID 是否被临时用例直接引用，不能只在系统命令或脚本中提及它们。少用 `fs_command` 等系统命令组件，仅在必要的构建和夹具准备等辅助场景使用，不能绕过新增组件的功能验证。
- 用例开发：`case` 指向本次新增或修改步骤的正式点分用例 ID，每个本次交付的用例都必须被本次新增或修改的计划引用，否则 DryRun 拒绝通过。混合任务需同时满足两类要求。
- 桥接层自动为本次写入的正式用例、计划及临时用例快照在顶层 `info` 后添加 `ai_created: true`。手动编辑保存保留标记，用例、计划和执行页面在名称旁显示绿色圆形 AI 标记。

执行前将 YAML 快照归档到 `build/ai_assisstant-<key>/cases/round-N/case-N.yml`，本轮执行的就是该快照。后续修订不覆盖前一轮快照，失败和取消也保留归档。`dryrun.json` 和交付区记录每条用例的名称、结果、归档路径及完整定义，点击名称在固定 960×720 的只读弹窗中查看，窄屏按视口限制尺寸，内容内部滚动。当前运行状态展示最新一轮，全部轮次 YAML 均在会话目录保留。

验证必须真实构建/运行本次交付的代码并断言输出，不能只检查源代码字符串、临时替身或旧版本。`functional_cases` 仅补充用例，旧用例不会因为写在这个字段里就变为新特性测试。

例如开发 `lpss.tool`，应覆盖 node list/info、topic list/info、service list/info 六项验收，并按需求验证 C++17~C++23，不能用 `lpss.basic_pubsub_pub_first` 替代。每项验证保存状态和输出证据，缺失验收、失败或跳过的新特性验证均不能标为开发成功，已有回归通过也不能代替。平台确实不支持的能力应明确说明，不伪造通过。

这里的 DryRun 会执行真实组件，可能创建文件、启动 Adapter 或操作测试设备，按正常集成测试环境使用。修改 Adapter 时自动执行 CMake 配置和编译，构建失败则不执行功能用例，可以通过环境变量 RMVL_DIR 指定 RMVL 包配置目录。会话脚本可在自己的目录配置独立 CMake 工程，验证代码与构建产物均保留供审核。

不设置固定 Token 预算或本地 Token 中止阈值。账号额度通过本机 `codex app-server` 的 `account/rateLimits/read` 读取，每 30 秒刷新，也接收 `account/rateLimits/updated` 通知。页面列出主要/次要时间窗口的真实剩余百分比，每个窗口进度条在剩余 **15% 及以下** 时变红。任意窗口达到该阈值，额度卡片的边框和背景、发送按钮同步告警，统一使用前端 `isLowQuota` 判定，恰好 15% 也告警。正常卡片为绿色边框/浅绿背景，进度条和按钮为蓝色。Token 实际用量另行累计，不据此推算账号额度。

额度接口未提供有效数据（例如未登录、网络不可用或不支持该接口的登录方式）时显示未知，不填充虚构的进度，也不由本地预算限制任务。读取额度仅使用 CLI 登录，不向前端发送账号标识或登录凭据。

任务日志和请求保存在 `kdt/tmp/ai`。取消或关闭 Agent 时中止当前子进程组，已写入的文件保留并在交付区列出，不自动回滚用户文件。

开发或方案会话结束时，在当前 `build/ai_assisstant-<key>` 中保存 `delivery.json`，包含精简摘要、结论、变更清单、存疑和 DryRun 用例快照，不保存账号额度和凭据。成功、失败、取消均可归档。原会话 key 是稳定身份，整理旧摘要时不改目录名。

AI 页面通过“历史会话”选择标准归档，使用 `GET /api/ai/sessions` 和 `GET /api/ai/sessions/:key`。必须开启 `--with-ai`，仅接受八位小写十六进制 key，只读工作区 `build/ai_assisstant-<key>/delivery.json`，拒绝符号链接、路径穿越、超大文件及无效格式。AI 或普通测试执行期间禁止打开历史。接口只返回独立历史快照，不覆盖 Agent 当前会话、不广播历史状态、不重放命令、不启动模型，也不写入正式源码。损坏和旧格式归档不会影响其他会话。

入口位于执行状态右侧，名称为“历史会话”。面板按会话创建时间倒序展示，没有创建时间的旧记录使用归档文件时间，支持搜索和逐条加载。删除经过弹窗确认后调用 `DELETE /api/ai/sessions/:key`，仅移除 `delivery.json` 历史记录，保留会话目录、YAML、验证代码和正式源码。删除不清空当前已经加载的展示内容，AI 或测试执行期间不允许删除。

打开历史后仅允许浏览、原文/Markdown 预览及原始/简洁输出切换，需求、模型、强度及发送均锁定。入口切换为“返回当前”，无需网络即可恢复当前需求草稿、模型、强度和实时工作区。历史快照与当前会话分离保存，实时状态持续更新但不覆盖历史展示，账号额度始终使用当前数据。更换 Agent 地址时清除历史视图和旧工作区，不把不同 Agent 的内容混在一起。

交付区包含可选的 `conclusion` 结论，模型无需单独结论时返回空字符串。只有咨询完成或审核与验证均通过时才发布结论，中间阶段的说明不作为最终结论。结论、最终变更、存疑内容和 DryRun 各部分仅在有实际内容时显示，不展示“暂无”占位或空测试统计。

任务工作区固定高度，需求提交后隐藏欢迎文案，工作流下方的需求、错误、响应在同一区域滚动，不随回复增长撑高面板。模型返回的嵌套错误会提取出真实原因，CLI 非零退出码作为附加信息保留。

响应区实时显示公开进展、显式计划、工具执行状态和阶段结果，命令详情可展开，完整命令输出保留在右侧日志。不展示内部 reasoning，也不把最终结构化 JSON 或工具原始载荷直接显示为响应。同一 CLI 调用中按 item ID 合并状态，命令只记录一次，完成后的聚合输出只打印一次，不同阶段或不同 item 执行相同命令仍独立记录。DryRun 的构建、回归测试和功能用例也显示中间状态。

响应区显示累计运行时间和距上次输出的等待时间，每秒由前端更新，不增加后端轮询。计时以 Agent 快照时间为锚点，兼容浏览器和远端机器时钟不一致，任务结束后冻结。额度刷新和 WebSocket 心跳不重置等待时间。60 秒没有新输出时显示提示，但不自动判失败或终止任务，原有单次 CLI 900 秒超时仍保留。断线时单独提示连接状态，重连后恢复计时与进展。

每个任务首次调用模型时记录 `[ai.codex]`，仅含可执行文件路径、CLI 版本、工作目录和配置目录，不含凭据。若本地交互式 Codex 能用而 Web 任务不能用，先对照这些字段，以及终端实际使用的模型、登录方式和 `--profile`。Web 使用的是启动 Agent 时继承的环境，不是浏览器所在设备的 Codex 配置，不自动切换账号或模型。配置分层见 [OpenAI 官方配置说明](https://learn.chatgpt.com/docs/config-file/config-basic)。
